# Plan: site redesign (landing page and daftar)

Spec: `docs/superpowers/specs/2026-10-17-site-redesign-landing-and-daftar-design.md` (approved 2026-10-17).
Inputs: Codex explore and research reports (2026-10-17), YouTube feed check.

## Facts settled by research

- Mail: the domain's MX records are Cloudflare Email Routing. The form sends through the Worker's
  `send_email` binding with the structured `send()` API (no MIME library). The sender is fixed as
  `website@ebrahimyoussef.com`, the visitor's address goes in `Reply-To`, and the subject is fixed.
- YouTube: the channel ID is `UCcKyBs8u4-ZEkJC-Z7FdVUQ`. The feed returns HTTP 200 with 11 entries,
  most of them Shorts from the Fastabiqu daily question series.
- Analytics: Cloudflare Web Analytics automatic setup injects the beacon at the edge. No code token is
  needed unless automatic setup fails.
- WhatsApp: `https://wa.me/201287877420?text=` plus `encodeURIComponent(message)`.
- i18n: Astro 7.1.6 built-in routing, `defaultLocale: "en"`, `prefixDefaultLocale: false`. Hreflang
  tags are written in the layout; the sitemap gets its own i18n option.

## Decisions made in planning (changes to the spec)

1. **No language memory.** The switch is a plain link to the other-language page. Remembering the
   choice conflicts with "never switch the visitor", and there is nothing to remember on a site with
   no redirect. Spec user story 30 becomes "open in English; the switch takes me to the same page in
   the other language".
2. **Two RSS feeds** in release 2: `/rss.xml` (English posts) and `/ar/rss.xml` (Arabic posts).
3. **Fonts: three families for both parts.** Reem Kufi (Arabic display), Aref Ruqaa (painted words
   and the inked name), Readex Pro (body text in both languages), all self-hosted through Fontsource.
   d28's Anton and Manrope are dropped, so the daftar uses the same three.
4. **The figures game gets Arabic labels** on `/ar/daftar`. Its logic, data and tests stay unchanged;
   only the UI strings take a locale.
5. **The YouTube shelf shows the latest 6 videos, Shorts included,** with Shorts as tall cards. The
   feed is mostly Shorts, so filtering them out would leave the shelf nearly empty.
6. **Duplicate form messages are accepted.** There is no database, and a double send is harmless.
   The submit button disables while a send is in flight. Rate limiting uses the Workers rate-limit
   binding.
7. **The CV PDF is generated once and committed.** A print HTML page is printed with the installed
   Edge (`--print-to-pdf`), and the result goes in the public folder. It is regenerated by hand when
   the CV changes. No browser dependency enters the site build.
8. **Who builds what.** Claude owns the visual layer: the final CSS and markup of every chapter and
   shelf in both directions (phase 0), and the review polish. Runners port that into Astro
   components, write the content modules, the Worker endpoint, the tests and the build check.

## Contact endpoint edge cases

| Concurrent operations | Partial failures | Abuse paths |
|---|---|---|
| A visitor double-clicks: the button disables while in flight. If two sends still land, two emails arrive, which is accepted. | Validation fails: 400 with the field to fix, and Turnstile is never called. | Non-POST: 405. Wrong content type or malformed body: 400. |
| A client retries after a timeout: possible duplicate email, accepted. The client never retries automatically. | Turnstile is unreachable or slow (5 s timeout): 503 with the "use WhatsApp or email" message, and nothing is sent. | Body over 8 KB: 413. Name over 100 characters, contact over 200 or message over 3000: 400. |
| Many visitors at once: no shared state, so there are no races. | Turnstile says invalid, expired or reused: 403 with the generic message, and nothing is sent. | Bots: Turnstile plus a hidden honeypot field (filled in means a silent 200 and no send) plus the rate limit (5 per minute per IP, then 429). |
| | Turnstile passes but the email send throws or times out: 502 with the "use WhatsApp or email" message. Success is never shown unless the send resolved. | Cross-origin posts: reject when `Origin` is not the site's own origin. Turnstile hostname must match. |
| | | Header injection: the subject is fixed and visitor input never enters `From`. `Reply-To` is set only when the contact value is a valid email. HTML is escaped in the email body. |

Invariant mapping: "an email is sent only for a valid, human, same-origin request" is enforced by a
single ordered guard sequence in the handler (method, origin, size, parse, honeypot, rate limit,
validate, Turnstile, then send). There is no state to keep consistent beyond that order.

### Release 1 (version 1.0.0): one runner chunk each, in order

1. **Content model.** New typed bilingual content modules replace `site.ts` and `products.ts`.
   Rewrite the content test first: six work entries in order, four services, five steps, six
   results, journey, every entry in both languages, WhatsApp URLs per language, no town name, no
   TikTok, no em dash or buzzword (fix the regex that currently matches plain hyphens), absolute links.
2. **Layout, i18n and Google removal.** Astro i18n config and sitemap i18n; the layout takes locale
   and path and writes `lang`, `dir`, canonical, hreflang (en, ar, x-default), `og:locale` and
   localized meta; header with the language switch, daftar link (hidden until release 2) and CV link;
   footer without the privacy control. Delete the consent component, the consent script and both
   consent tests; remove the privacy-region route from the Worker. Empty landing pages for `/` and
   `/ar/`. Start test: `pnpm astro check` and a build.
3. **Tokens and fonts.** Rewrite global CSS tokens from the phase 0 mocks, swap the Fontsource
   packages, keep every token the game CSS references, keep the reduced-motion rules. Rewrite the
   design system doc.
4. **Landing chapters.** Port d29 from the mock into Astro components rendered from the content
   modules (no `innerHTML`). Client scripts: chapter pinning (RTL-aware), reveal, copy email. The
   form markup and Cal.com link (renders nothing while its setting is empty) are included, and the
   form posts to `/api/contact`.
5. **Contact endpoint.** Tests first, from the edge-case table, calling the handler with a fake env
   (fake `CONTACT_EMAIL.send`, stubbed Turnstile fetch, fake rate limiter). Then the handler and the
   wrangler bindings (`send_email`, rate limit, secret declared but not committed). Client-side
   submit with Turnstile and the three outcome messages.
6. **Build check rewrite.** `verify-build` reads every built page: both landing pages, both case
   studies, the CV PDF (`%PDF` header, non-zero size), `lang`/`dir`, hreflang pairs, canonical per
   page, structured data, social meta; fails on any Google tag, consent or privacy-region marker,
   TikTok link, empty link or placeholder. From here `pnpm verify` must pass after every chunk.
7. **Fastabiqu case study.** English and Arabic pages from the content modules, linked from the
   Work chapter.
8. **CV PDF and release assets.** Claude designs the print page; the runner prints it with Edge and
   commits the PDF. Regenerate the OG image, update the manifest colors, bump every version field to
   1.0.0.

4. **Blog routes and RSS.** Post page, tag pages, share link, the "first post soon" state, two feeds.
5. **Daftar build check and release.** Extend `verify-build` to the daftar pages and feeds, bump
   every version field to 1.1.0.
